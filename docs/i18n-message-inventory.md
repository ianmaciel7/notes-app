# i18n Message Inventory

## Overview and Architecture

The application implements a type-safe internationalization architecture supporting `en` (default) and `pt-BR`.

- **Contract**: Defined by `AppMessages` in `src/lib/i18n/types.ts`. Catalogs in `src/app/[lang]/dictionaries/en.json` and `src/app/[lang]/dictionaries/pt-BR.json` are validated against this contract.
- **Server Components**: Load localized dictionaries asynchronously via `getDictionary(lang)` in `src/app/[lang]/dictionaries.ts`.
- **Client Components**: Access translations via `useI18n().t` through `I18nProvider` in `src/lib/i18n/provider.tsx`, rendered by the root locale layout (`src/app/[lang]/layout.tsx`).
- **Routing & Proxy**: Handled by `src/proxy.ts` with cookie (`NEXT_LOCALE`) and `Accept-Language` header negotiation, preserving pathnames and query strings.
- **Error Normalization**: Handled by `getAuthErrorMessage(error, t)` in `src/lib/i18n/auth-errors.ts`, mapping Firebase error codes to translated catalog messages.

## Authentication Error Normalization

Direct rendering of raw exceptions (`error.message` or `String(error)`) has been eliminated in favor of `getAuthErrorMessage(error, t)` from `src/lib/i18n/auth-errors.ts`:

- **Known Error Code Mapping**:
  - `auth/invalid-credential`, `auth/wrong-password`, `auth/user-not-found`, `auth/invalid-email`, `auth/invalid-verification-code` → `errors.auth.invalidCredentials`
  - `auth/email-already-in-use` → `errors.auth.emailAlreadyInUse`
  - `auth/user-disabled` → `errors.auth.accountDisabled`
  - `auth/too-many-requests` → `errors.auth.tooManyRequests`
  - `auth/operation-not-allowed` → `errors.auth.operationNotAllowed`
  - `auth/requires-recent-login` → `errors.auth.requiresRecentLogin`
  - `auth/code-expired`, `auth/session-expired` → `errors.auth.sessionExpired`
  - `auth/network-request-failed` → `errors.generic.network`
- **Fallback Policy**:
  - Unknown error codes or non-object errors safely fall back to `errors.auth.unknown` (`"Unable to complete authentication. Please try again."` / `"Não foi possível concluir a autenticação. Tente novamente."`).
- **Consumers**:
  - `src/components/sign-in-auth-form.tsx`
  - `src/components/sms-multi-factor-assertion-form.tsx`
  - `src/components/totp-multi-factor-assertion-form.tsx`

## Boundary with Firebase UI Translations

- **Firebase-Owned UI**: Labels, input prompts, and built-in schema validation messages managed by `@firebase-oss/ui-react` continue to use `getTranslation(ui, ...)` (e.g. `labels.signIn`, `labels.emailAddress`, `labels.password`, `prompts.noAccount`).
- **App-Owned UI**: Custom application screens, shared layout elements, dialogs, pagination, questionnaires, and top-level error displays consume the `useI18n()` hook or server dictionaries.
