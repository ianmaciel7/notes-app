# Next.js App Router Project Rules

## Context

- Next.js 16.3.8 App Router.
- React 19.2.8 with React Compiler.
- TypeScript 5.9 strict typing with `next typegen`.
- Biome 2.4.2 formatter and linter.

## Architecture & Rendering

- **App Router Only**: Do not introduce Pages Router conventions or APIs (`next/router`, `next/head`, `next/document`, `getServerSideProps`, `getStaticProps`, `getStaticPaths`, `getInitialProps`).
- **Server Components by Default**: All components are React Server Components unless client capabilities are strictly required.
- **Minimal Client Boundaries**: Use `"use client"` only for interactive leaves requiring client state, effects, event handlers, browser APIs, or client-only packages. Keep client boundaries as small and deep as practical.
- **Server/Client Serialization**: Pass only minimal, serializable DTOs across the Server-to-Client component boundary.
- **Allowed `src/` Root Files**: Only official Next.js root convention files (`proxy.ts`, `middleware.ts`, `instrumentation.ts`) may reside directly under `src/`. All other application code must live in standard subdirectories (`src/app`, `src/components`, `src/hooks`, `src/lib`, `src/styles`), and tests belong under `tests/` or module subdirectories. Enforced by Dependency Cruiser rule `src-root-allowed-files-only`.

## Data Access & Caching

- **Direct Server-Side Data Access**: Read database and server-side data directly in Server Components or dedicated server-only modules.
- **No Self-Fetch**: Never call the application's internal Route Handlers via `fetch()` from a Server Component for ordinary data access.
- **Concurrency & Waterfalls**: Parallelize independent I/O operations (`Promise.all`) rather than creating sequential waterfall awaits.
- **Streaming & Suspense**: Wrap slow or dynamic data dependencies in `<Suspense>` boundaries.
- **Next.js 16 Cache Primitives**: Use modern `"use cache"`, `cacheLife`, and `cacheTag`.
- **Cache Invalidation**: Use `revalidatePath`, `revalidateTag(tag, profile)`, and `updateTag` intentionally after mutations.
- **No Deprecated Cache APIs**: Never use `unstable_cacheLife`, `unstable_cacheTag`, `unstable_noStore`, or `unstable_after`.

## Request APIs & Routing

- **Async Request APIs**: Always treat request APIs as asynchronous in Next.js 16:
  - `await cookies()`
  - `await headers()`
  - `await draftMode()`
  - `await params` / `await searchParams` (in page and layout props)
- **Route Types**: Prefer route-aware types generated by `next typegen`: `PageProps`, `LayoutProps`, and `RouteContext`.
- **Redirects**: Never wrap `redirect()` or `notFound()` calls inside generic `try/catch` blocks that swallow Next.js control flow exceptions.

## Server Actions & Route Handlers

- **Public Attack Surface**: Treat every Server Action and Route Handler as a public, untrusted HTTP endpoint.
- **Runtime Validation**: Always validate input schemas (e.g., Zod) on all parameters, request bodies, and query parameters.
- **Explicit Authorization**: Verify authentication and concrete resource ownership/permissions at the operation boundary. Never rely on client state, role claims, or middleware alone for authorization.
- **Data Minimization**: Never expose sensitive internal model fields or infrastructure secrets in action returns or handler responses.

## Navigation & Media

- **Navigation**: Use `next/link` for internal application links to enable client-side navigation and prefetching.
- **Images**: Use `next/image` with remote patterns configured via `images.remotePatterns` in `next.config.ts`. Deprecated `images.domains` is prohibited.
- **Fonts & Scripts**: Use `next/font` for web font optimization and `next/script` for third-party scripts.

## Guard Stack & Verification

Enforcement follows the hierarchy:
```text
Next.js > TypeScript > Biome > GritQL > Vitest/Playwright > Code Review
```

- Prefer framework-native and compiler guarantees over duplicate GritQL heuristics.
- Always run fast verification during changes: `pnpm run verify:changed`.
