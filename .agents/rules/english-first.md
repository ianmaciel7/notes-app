# english-first

Always use English for repository-facing and code-facing artifacts, including:
- AGENTS rules and instructions
- PR descriptions and summaries
- Markdown docs and project notes
- Commit messages and changelogs
- Variable names, function names, comments, and API-facing text
- OpenSpec artifacts (proposals, deltas, tasks, requirements, specs)

Do not use Portuguese or mixed language in tracked repository files.

Reasoning policy:
- Use English for consistency with automation, contributors, and long-term maintainability.
- If input arrives in another language, translate intent into English in repository artifacts.

Allowed exception:
- End-user product UI copy may be localized only when explicitly required by product requirements.
