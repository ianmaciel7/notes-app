# Browser-first research

When a browser or internet-capable tool is available, prefer using it for tasks that depend on external pages, current facts, live product behavior, or reference UI parity.

## Required behavior

- Use available browser or internet tools before relying on memory for information that may have changed.
- Prefer direct inspection of the linked page, app, documentation, or reference UI when the user provides a URL.
- For UI parity work, inspect the live or captured reference state with the browser when reusable evidence is missing, stale, or incomplete.
- Capture or cite evidence from the browser when the result depends on a live page, product state, visual comparison, or current documentation.
- If browser or internet access is unavailable, blocked, or unnecessary for a stable local-only task, say so briefly and continue with the best available local evidence.

## Boundaries

- Do not browse just to re-check stable repository-local facts that can be read from source files.
- Do not capture or persist cookies, tokens, private storage values, unrelated personal content, or complete authenticated exports.
- Follow `docs/references/reference-evidence-workflow.md` when saving reusable external UI evidence.
