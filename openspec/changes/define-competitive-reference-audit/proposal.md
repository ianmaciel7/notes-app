## Why

Competitive reference evidence must stay separate from product requirements. This change defines how to inspect reference products safely and classify observations without copying branding, private APIs, undisclosed algorithms, or unverified behavior.

## What Changes

- Define reference control inventory requirements.
- Define post-interaction outcome and interaction-state evidence requirements.
- Define object lifecycle audit coverage.
- Define confidence classification.
- Define safety boundaries and repository-safe evidence references.

## Impact

- Planning only; no runtime code changes in this change.
- Product changes may cite this audit evidence, but inferred or unknown behavior must not become confirmed product requirements.
